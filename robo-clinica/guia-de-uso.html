01 · O QUE MUDOU NESSA VERSÃO

Mais caprichado que o rascunho inicial

A melhoria principal: dados editáveis sem mexer em código

Antes, pra trocar um preço ou horário, alguém tinha que editar código e fazer deploy de novo. Agora os dados da clínica moram num bancozinho (SQLite) que dá pra editar numa telinha visual — sem tocar em código, sem redeploy.

Outros reforços

  • Validação (Zod): se chegar uma mensagem em formato estranho, o sistema ignora em vez de quebrar.
  • Proteção contra duplicidade: WhatsApp e Instagram às vezes reenviam o mesmo aviso — agora o bot não responde duas vezes pra mesma mensagem.
02 · O QUE TEM DENTRO DO ZIP

Mapa dos arquivos, em português simples

prisma/a "receita" do banco de dados — onde ficam os pacotes, preços e horários
src/server.tsliga tudo, é o ponto de partida do backend
src/routes/recebe as mensagens do WhatsApp e do Instagram
src/services/ia.tsconversa com a Claude e monta a resposta
src/services/baseDeConhecimento.tsbusca os dados da clínica no banco
.env.exampleonde colam as chaves/senhas (copiar pra .env)
docker-compose.ymlsobe tudo de uma vez (WhatsApp + backend)
03 · PASSO A PASSO

Do zip até o cliente testando

1

Preparar as chaves

Duplica o arquivo de exemplo e preenche

cp .env.example .env

Abre o .env e preenche: chave da Anthropic (console.anthropic.com), uma chave qualquer pra EVOLUTION_API_KEY (só precisa ser igual nos dois lugares), e o número humano de backup.

2

Instalar e criar o banco

Roda numa máquina com internet normal

npm install
npm run migrate
npm run seed

O npm install já baixa e prepara o Prisma sozinho. Se aparecer erro de rede aqui, é ambiente restrito (sandbox/firewall corporativo) — num PC normal isso roda liso.

3

Preencher os dados reais

A parte que qualquer um da equipe consegue fazer

npm run studio

Abre uma telinha no navegador. Edita ClinicaConfig (nome, endereço, horário, pagamento, cancelamento) e adiciona um Pacote pra cada serviço real da clínica. É só isso que muda quando o cliente pedir ajuste de preço depois.

4

Subir tudo com Docker

WhatsApp + backend juntos

docker compose up -d --build
docker compose exec backend npm run migrate:deploy
docker compose exec backend npm run seed
5

Conectar o WhatsApp

Com um número de teste primeiro, nunca o da clínica ainda

curl -X POST http://localhost:8080/instance/create \
  -H "apikey: SUA_CHAVE" \
  -d '{"instanceName":"clinica","qrcode":true}'

Escaneia o QR code (Aparelhos conectados → Conectar um aparelho) e configura o webhook apontando pro backend — os comandos completos estão no README.

6

Conectar o Instagram

Só precisa da conta da clínica como "tester"

  • Conta Business/Creator vinculada a uma Página do Facebook.
  • App criado em developers.facebook.com com o produto de Instagram.
  • Clínica adicionada como testadora — sem precisar da revisão completa da Meta.
7

Testar antes de entregar

Checklist final

  • Perguntou os pacotes/valores reais e bateu com o que está no Prisma Studio?
  • Mandou uma pergunta fora do escopo (ex: reclamação) e o bot encaminhou pro humano?
  • Testou pelo WhatsApp e pelo Instagram?
  • Avisou o cliente do custo mensal (VPS + IA)?
  • Combinou quem cuida da manutenção se algo travar?

Nota honesta

Eu revisei e testei o máximo que deu no meu ambiente aqui, mas o sandbox onde eu rodo bloqueia o domínio que o Prisma usa pra baixar o motor dele — então o npm install completo só valida de verdade na máquina de vocês, com internet normal. O resto (estrutura, rotas, lógica) foi checado com tsc e revisão linha a linha.

Próximo passo

Assim que tiverem os dados reais da clínica (pacotes, valores, horários), joguem no Prisma Studio e testem uma rodada de perguntas difíceis antes de conectar o número de verdade.
